# 12 — Audio Production Specification

Blueprint §7 requires a production spec for sample rate, loudness normalisation, peak ceiling, silence padding, duration
and transcript. This is it. Implemented by `scripts/audio_produce.ts` (admin job `audio:produce`) behind a provider interface.

## 1. Inventory (from `/seed`)
| Asset group | Count | Source field | Voice |
|---|---|---|---|
| Listening stimuli | 21 | `listening.json → stimuli[].text` (admin script) | 1–3 speakers per `speaker_count`; accents rotated |
| Speaking — Sentence Reconstruction | 6 | `speaking_tasks.json → audio_script` (SR) | single, neutral clear voice |
| Speaking — Retell/Summarise messages | 6 | `audio_script` (RT) | single voice, different from SR voice |
| Speaking — Interaction interlocutor lines | 12 | `interlocutor_line` (INT1/INT2) | one consistent "interlocutor" voice per route |
| Writing — listen-to-write diagnostics | 6 | `writing_tasks.json → audio_script` (D) | single, neutral clear voice |
| Worked-example demo tone | 1 | generated 3 s 440 Hz sine at −20 dBFS | — |

## 2. Providers
- **Default: Gemini TTS** (`MODEL_TTS`, multi-speaker mode for 2–3 speaker scripts). Parse `A:`/`B:`/`C:` turns into
  speaker segments; assign voices per the rotation plan; pass style hints ("natural, clear, moderate pace").
- **Optional: ElevenLabs adapter** (`ELEVENLABS_API_KEY`) — useful if you want to reuse an existing voice cast for
  accent rotation (British/Australian voices). Same interface: `synthesize({segments:[{speaker, text}], voices, rateHint}) → wav`.
- Interface: `TtsProvider.synthesize(request): Promise<{wavPath, provider, voiceIds, durationSec}>`; provider name and voice
  IDs stored on `stimulus_admin.voice_cast`.

## 3. Speech-rate targets (indicative words per minute; blueprint §7)
| Level | Target wpm | Tolerance |
|---|---|---|
| Pre-A1 | 100–110 | ±8% of `words / target_wpm × 60` |
| A1 | 110–125 | same |
| A2 | 130–145 | same |
| B1 | 140–155 | same |
| B2 | 145–160 | same |
| C1 | 150–165 | same |
| C2 | 150–170 | same |

Each stimulus carries `target_wpm` and `est_duration_sec` (`word_count / target_wpm × 60`). Measured speech duration
(excluding padding and inter-turn pauses > 0.6 s) must fall within tolerance; otherwise regenerate with a rate hint, and
only as a last resort time-stretch with `ffmpeg -af atempo` within 0.93–1.07 (never beyond; log it).

## 4. Accent rotation plan (difficulty must come from language/discourse, not accent)
- Pool: General British, General American, Australian, Irish/Scottish (clear), plus a clear non-native-but-standard voice
  where the provider offers one. Rotate so that within any band no more than 2 of 3 stimuli share an accent and across
  bands each accent appears at multiple levels. Record the plan in `seed/audio_plan.json` (generated by the job).
- Speaker A/B/C within a dialogue use distinct voices (gender/timbre) so turn tracking is achievable from voice alone.
- Speaking prompt audio (SR/RT/INT/listen-to-write) uses a single standard-British and a single standard-American voice
  alternating by route, kept identical within a route.

## 5. Processing chain (ffmpeg, deterministic)
1. Provider output → mono, 48 kHz, 24-bit WAV master (`assets/master/{id}.wav`).
2. Trim leading/trailing silence below −50 dBFS, then pad: **0.5 s lead-in, 1.0 s tail** (digital silence).
3. Loudness normalise: `loudnorm` two-pass to **I = −16 LUFS**, **LRA ≤ 11**, **true peak ≤ −1.5 dBTP**.
4. Deliverables: `{id}.opus` (libopus 48 kb/s mono) as primary, `{id}.mp3` (128 kb/s) fallback; store `codec`, `durationSec`,
   `loudnessLufs`, `truePeakDb`, `sha256` on the stimulus/task document; masters stay in an admin-only bucket path.
5. Number and time rendering: normalise scripts for TTS (e.g. "11:20" → "eleven twenty", "10:15" → "ten fifteen",
   "08:40" → "eight forty", "£12" → "twelve pounds") **without** changing the stored admin script.
6. No beeps or announcer cues in test audio; the UI controls playback.

## 6. QC report (`assets/qc_report.json` + markdown)
Per asset: provider, voices, words, target wpm, measured wpm, duration, in-tolerance flag, LUFS, true peak, clipping
samples (must be 0), silence padding check, transcript match (ASR via `MODEL_FAST` transcribe → word error rate vs script
< 5% or flag `transcript_mismatch`), checksum. Job fails if any listening asset is out of tolerance or has WER ≥ 10%.

## 7. Storage & linking
`audio/stimuli/{stimulus_id}/v{n}.opus|mp3`, `audio/prompts/{task_id}/v{n}.opus|mp3`. The loader/job updates
`stimuli_listening.media` and `speaking_tasks.audio` / `writing_tasks.audio`. Signed URLs only (TTL 10 min).
Re-running the job with an unchanged script and provider is a no-op (checksum of normalised script + voice plan).
